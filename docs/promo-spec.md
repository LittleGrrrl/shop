# Промокоды в корзине — feature spec

> Пример заполненной мини-спецификации для задания «Корзина + промокод». Функция разбита на три шага — каждый со своим scope и критериями приёмки. В реальном проекте это может быть три отдельных файла или один, как здесь.

## Общий scope задачи

Ввод промокода в корзине, применение скидки к итоговой сумме, сохранение между сессиями.

## Out-of-scope

- Серверная валидация промокодов. Список валидных кодов хранится в клиенте.
- Истечение срока действия промокодов.
- Несколько промокодов одновременно. Применяется только один.
- Разные типы скидок (абсолютная, бесплатная доставка). Только процент.
- Регистрозависимость. `SALE15` и `sale15` — один код.

## Constraints

- Не менять структуру данных товаров в корзине.
- Не ломать существующий расчёт итога (текущие тесты должны продолжать проходить).
- localStorage-ключ: `appliedPromo`, значение — JSON `{ code, discount }`.

---

## Шаг 1. Ввод и валидация

### Scope

UI для ввода промокода: инпут, кнопка «Применить», зона для сообщения о результате. Валидация по списку валидных кодов. Кнопка Удалить.

### Список валидных кодов (пока захардкожен в `src/data/promo.js`)

Валидные коды: `PROMO_CODES = { SALE15: 15, SALE20: 20, WELCOME10: 10 }` (проценты скидки).
Функция `validatePromo(code)` возвращает `{ valid: true, discount }` или `{ valid: false }`. Регистр кода не важен.

### Acceptance criteria

1. Ввод `SALE15` + «Применить» → под инпутом появляется сообщение «Промокод применён: −15%» (зелёное).
2. Ввод `FAKECODE` + «Применить» → сообщение «Промокод недействителен» (красное).
3. Ввод пустой строки → кнопка disabled.
4. Регистр не важен: `sale15` = `SALE15`.
5. После успешного применения инпут переходит в состояние «применён», появляется кнопка Удалить.
6. Клик по Удалить сбрасывает промокод, инпут снова пустой.

### Test plan

- Юнит-тест `validatePromo(code)`: валидный код, невалидный код, пустая строка, смешанный регистр.

## Шаг 2. Пересчёт итога

### Scope

Применение процентной скидки к `subtotal` корзины. Без промокода в блоке итогов отображается только «Итого: Z». После применения промокода над итогом появляется строка «Скидка: −N%» с суммой скидки «−Y».

### Acceptance criteria

1. Без промокода: итог = сумма товаров.
2. С промокодом `SALE15` и товарами на 1000 ₽: скидка 150 ₽, итог 850 ₽.
3. Скидка округляется до целого рубля по правилам `Math.round`.
4. После отмены промокода (шаг 1, п. 6) итог возвращается к исходному значению.
5. В блоке итогов строка «Скидка: −N%» и сумма скидки появляются только когда промокод применён.

### Test plan

- Юнит-тесты `getSubtotal(items)` и `applyDiscount(subtotal, discountPercent)`: учёт скидок товаров и количества, отсутствие промоскидки, разные проценты, округление, нулевой `subtotal`.
- Интеграционный тест корзины: применение и удаление промокода меняет итог и видимость строки скидки.

---

## Шаг 3. Сохранение в localStorage

### Scope

Применённый промокод сохраняется в `localStorage` и восстанавливается при следующем открытии корзины.

### Acceptance criteria

1. Применение `SALE15` → в `localStorage` под ключом `appliedPromo` лежит `{"code":"SALE15","discount":15}`.
2. Обновление страницы → промокод снова применён, итог пересчитан.
3. Отмена промокода → ключ удаляется.
4. Если в `localStorage` лежит невалидный код (изменился список, подставили руками) → при загрузке код игнорируется, ключ очищается.
5. Очистка корзины → промокод тоже сбрасывается.

### Test plan

- Юнит-тест чтения/записи в мок `localStorage`.
- Ручная проверка: применить, обновить, отменить, почистить корзину.

## Критерии рефакторинга (шаг 4 задания)

После реализации расчёт итога разбит на:

- `getSubtotal(items)` — сумма товаров до скидки;
- `applyDiscount(subtotal, discountPercent)` — сумма после применения процента;
- композицию этих функций непосредственно в `CartPage`.

Обе функции чистые, без побочных эффектов и покрыты юнит-тестами. Отдельная `calculateTotal(items, promoDiscount)` не добавлена: сейчас она была бы тонкой обёрткой без самостоятельной логики и единственным потребителем остался бы `CartPage`.

## Decision log (заполняется после реализации)

- Список кодов и `validatePromo` вынесены в `src/data/promo.js`. Перед проверкой код очищается от пробелов по краям и приводится к верхнему регистру, поэтому в состоянии и `localStorage` хранится нормализованный код.
- `subtotal` считается по фактической цене товара после его собственной скидки с учётом количества. Промоскидка применяется к полученной сумме, а итог округляется до целого рубля через `Math.round`.
- После успешного применения поле становится `readOnly`, кнопка «Применить» заменяется на «Удалить». Строка скидки в итогах показывается только для активного промокода.
- Применённый промокод хранится под ключом `appliedPromo` в формате `{ code, discount }`. Состояние корзины лениво восстанавливается из `localStorage` при создании компонента; удаление промокода очищает и состояние, и ключ.
- При восстановлении код повторно проверяется через `validatePromo`, а процент берётся из актуального списка `PROMO_CODES`, поэтому сохранённое значение `discount` не считается доверенным. Невалидное или повреждённое значение удаляется из `localStorage`.
- Когда корзина становится пустой, промокод сбрасывается в состоянии компонента и удаляется из `localStorage`.
- Отдельная `calculateTotal` не введена: `CartPage` последовательно вызывает `getSubtotal` и `applyDiscount`, не создавая функцию-обёртку без новой логики.
