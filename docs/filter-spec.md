# Фильтры каталога — feature spec

> Пример заполненной спецификации. Не шаблон: если ваша задача отличается, меняйте формулировки, добавляйте и убирайте секции. Цель — показать планку «достаточно точно, чтобы агент сделал предсказуемо».

## Scope

Фильтрация карточек каталога по двум параметрам:

- диапазон цен (минимальная и максимальная, обе границы опциональны);
- категория (множественный выбор из трёх категорий: «Одежда», «Обувь», «Аксессуары»).

Состояние фильтров синхронизируется с URL через query-параметры `?minPrice=1000&maxPrice=3000&categories=Одежда,Обувь`.

## Out-of-scope

- Серверная фильтрация. Фильтруем на клиенте по загруженному массиву товаров.
- Пагинация, сортировка, поиск по названию.
- Фильтр по бренду, рейтингу, наличию на складе.
- Кастомные диапазоны цен (пресеты вроде «до 1000»).

## Interfaces

Чистая функция фильтрации в `src/utils/filters.js`:

```js
filterProducts(products, { minPrice, maxPrice, categories });
```

- `minPrice` / `maxPrice` — границы итоговой цены после скидки включительно, каждая опциональна.
- `categories` — массив строк; пустой или `undefined` означает «без фильтра по категории».
- Возвращает новый отфильтрованный массив, вход не мутирует.

Компонент `src/features/catalog/CatalogFilters.jsx` принимает доступные категории (массив строк) и текущие значения фильтров, об изменениях сообщает через callback. `CatalogPage` читает фильтры из URL и прогоняет товары через `filterProducts`.

## Constraints

- Не менять структуру данных товаров (`id, name, price, discount, category, inStock, image, description`).
- Не добавлять внешние зависимости. URL-синхронизация через встроенный роутер проекта.

## Acceptance criteria

1. **Ценовой фильтр.** Ввод `1000` в «от» и `3000` в «до» оставляет товары с итоговой ценой после скидки в диапазоне `[1000, 3000]`. Открытый интервал работает: только «от» — всё от этой цены и выше.
2. **Категорийный фильтр.** Выбор «Одежда» показывает товары с `category === 'Одежда'`. Выбор двух категорий — объединение (OR).
3. **Комбинация.** Цена и категория применяются одновременно (AND между типами, OR внутри типа).
4. **Синхронизация с URL.** После изменения фильтра URL обновляется без перезагрузки. Открытие URL с параметрами восстанавливает состояние.
5. **Счётчик.** Над списком видно количество найденных товаров: «Найдено: 6».
6. **Пустой результат.** Если ни один товар не подошёл — сообщение «Товары не найдены» и кнопка «Сбросить фильтры».
7. **Доступность.** Все элементы управления фильтра доступны с клавиатуры, у чекбоксов категорий есть связанные `<label>`.

## Test plan

Юнит-тест для чистой функции `filterProducts`:

- пустые фильтры возвращают весь массив;
- только цена: границы включительно, открытый интервал;
- только категории: одна категория, несколько категорий;
- комбинация: цена + одна категория, цена + несколько;
- ни один товар не подходит: возвращается пустой массив.

Ручная проверка в браузере — сценарии 1–6 из критериев приёмки + обновление страницы с применёнными фильтрами.
