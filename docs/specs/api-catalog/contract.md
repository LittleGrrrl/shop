# Контракт API каталога товаров

## Endpoint

`GET /api/v2/products` — относительный путь.

В разработке — через моки, в продакшене — через поставщика `supplier.example.com/api/v2`.

## Авторизация

Заголовок `X-Api-Key`, значение из `import.meta.env.VITE_API_KEY`.

## Параметры запроса

| Параметр | Тип | Ограничения |
| --- | --- | --- |
| `category` | string | |
| `page` | int | По умолчанию 1 |
| `limit` | int | Максимум 50 |

## Формат успешного ответа (200)

```text
{
  "items": [{
    "item_id": number,
    "item_name": "string",
    "item_price": number,
    "in_stock": boolean,
    "category": "string",
    "discount": number,
    "image": "string",
    "description": "string"
  }],
  "total": number,
  "page": number
}
```

## Коды ошибок

- 400 — неверные параметры запроса.
- 401 — невалидный API-ключ.
- 429 — превышение лимита, заголовок `Retry-After` содержит секунды ожидания.
- 500, 502, 503 — сбой на стороне поставщика.

## Лимиты и таймаут

Лимит: 100 запросов в минуту.

Таймаут: 5 секунд.

## Acceptance criteria

- `npm test` проходит. Покрыты сценарии: основной сценарий, таймаут, 5xx, фолбэк на кеш, `INVALID_RESPONSE`.
- `ApiError` — единственный тип ошибки, который выходит наружу из модуля.
- Интерфейс отображает четыре состояния: `loading`, `retrying`, `fallback`, `failed`.
- `VITE_USE_MOCK_DATA=true` переключает источник данных без правок кода.
- `VITE_API_KEY` нигде не коммитится: `.env` в `.gitignore`, `.env.example` с пустым значением.
- `npm run lint` без ошибок уровня error. `npm run build` без ошибок.

## Rollback

- Переключатель `VITE_USE_MOCK_DATA` в переменных окружения. При `"true"` — `useProducts` отдаёт данные из `src/api/mocks/catalog.json`.
- Значение читается из `import.meta.env` при старте приложения; смена `VITE_USE_MOCK_DATA` требует перезапуска dev-сервера (для прод-сборки — пересборки).
- Файл `src/api/mocks/catalog.json` содержит шесть товаров в формате поставщика (поля `item_id`, `item_name`, `item_price`, `in_stock` + категория/скидка/картинка/описание). Мок проходит через тот же `adaptProductList`, что и реальный ответ API.

## Quality gates

- `npm test` зелёный: покрыты четыре базовых сценария (основной сценарий, таймаут, 5xx, фолбэк на кеш) и сценарий изменения формата ответа (`INVALID_RESPONSE`).
- `npm run lint` без ошибок. `npm run build` без ошибок.
- Ручная проверка: каталог загружается с реальным API, карточки отображаются.
- Ручная проверка: при недоступном API каталог показывает кешированные данные с предупреждением.
- Ручная проверка: при `VITE_USE_MOCK_DATA=true` каталог показывает фикстуры.
- Время загрузки каталога < 3 с при ответе API < 1 с.
